# EasyJTAG completion and logging synchronization

The shared Odin engine and ABI 1.11 already match the latest EasyJTAG protocol implementation. No protocol, framing, partition policy, geometry validation or manufacturer verification code changed in this synchronization.

## Worker lifetime

EasyJTAG's post-flash crash was an execute access violation in the MinGW DLL's `emutls_destroy`, after the per-operation loader had unmapped that DLL but before its worker thread finished. EasyJTAG now pins its validated DLL through process exit. This is a host-loader correction, not an engine protocol change.

OdinBCC binds the engine functions directly into its classic-Borland executable. Engine code already remains available for the executable's lifetime, so no DLL pin, dynamic engine loader or MinGW runtime is added here. The normal system WinUSB/RichEdit loads keep their existing lifetimes. EasyJTAG's wxSmith controls and CrashRpt callback are application-specific and are not dependencies of this native UI.

## Persistent session logs

The native `logs/odin-*.log` files remain beside the running executable and retain the existing Save log action. Records now include local timestamps and UTF-8 text. A C++03 critical-section-protected sink handles partial writes and flushes each semantic record with `FlushFileBuffers`.

Worker messages reach disk before `PostMessage`, and the final result, transfer summary, reboot warning and backend completion state are saved before worker exit. GUI handling no longer appends those records a second time. File-only completion markers cover pending updates, worker join, result display/destruction and restored controls. Packet/byte updates remain coalesced. An unavailable or failed session file produces one visible warning while preserving operation behavior.

## Verification and deployment

Run `py -3 tests/run_tests.py --build-app --configuration Debug` and the corresponding Release command. The runner includes the native session-log tests, the eight engine/UI-logic suites, manifest regressions and the owned offline UI tests. Logger tests cover Unicode paths/text, timestamps, immediately readable flushed records, concurrent worker writes, partial writes, write/flush failures and sticky error state. UI assertions cover completion markers, cancellation and duplicate prevention without changing the concise on-screen log.

Build manifests include `src/SessionLog.h`. The IDE lists it alongside the native UI header. Publish the executable returned by `build.verified_output("Release")` with its matching manifest and notices to `dist/`; verify the source/header/object/executable hashes and system-only PE imports before packaging. Current binary identities and verification results are in `native-build-verification.json`.

Physical flashing and recovery are not exercised by this synchronization. Offline file verification and fake transports do not establish physical compatibility with every phone or protocol.
